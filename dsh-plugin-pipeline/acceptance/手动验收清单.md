## 0. 历史排障摘要（2026-11-07，已闭环）

当时现象：完整重启宿主后点击「一键上线」仍返回
`transport failure for /dsh-pipeline/run: HTTP 405`。对真实进程发请求对照：
`GET /completed-ding/foreground` = 200（第三方插件路由正常），
`GET /dsh-pipeline/doctor` = 404（本插件路由一条都没挂上）。

根因链（三层，逐层修复）：

1. **两段 channel 非法** → DSH 要求 `^\/[A-Za-z0-9._~-]+$`；改为单段 `/dsh-pipeline`。
2. **未返回 DSH 信封 / `effect` 误用** → handler 改返回 `{ ok:true, value }`；
   `rpc.handle()` 返回的是注销函数，`ctx.effect(() => dispose, ...)` 必须返回该函数本身，
   写成 `effect(() => dispose())` 会刚注册就撤销，POST 落到静态 fallback 返回 405。
3. **注册时机（最终根因）** → 缺模块级 `export const inject = ['webServer']`，
   只在 `apply()` 内用 `ctx.inject(['connection'], ...)` 等待并不可靠，且 inject 子 fiber
   异常会被 loader 静默吞掉（插件显示 ACTIVE、路由却没注册）。修复为模块级 inject、
   路径 A 官方 RPC、路径 B `webServer.register()` 兜底、运行时 trace 日志、
   `probe_live_route.py` 不点 UI 直接探测真实宿主。

详细规范与代码级说明见 Skill 的 `references/plugin-spec.md` 第 11 节与
`references/acceptance-and-troubleshooting.md`。

后续两次失败均与代码无关：一次是未完整重启；一次是把宿主主程序 `.exe`
误填进「插件源码目录」输入框，返回 `SRC_NOT_FOUND`。正确值是含 `package.json` 的目录。
